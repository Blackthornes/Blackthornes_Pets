## What this addon is for

Everything around pets for **hunters and warlocks**: the hunter's pet and
stable, the warlock's demons. The first feature is the pet status panel in
the pets window and the hunter's feed warning (`Logic/PetStatus.lua`), built
on the `C_PetInfo` calls the probe found, and the food helper
(`Logic/Food.lua`, `Data/PetFood.lua`, foods by item ID with their
English name, IDs filled in by `tools/petfood_ids.py` from the spawn database, the
client's diet words mapped in `DIET_WORDS` so a German client works too):
food in the bags by diet, a secure
Feed button kept outside the window so the window still closes in combat,
a low food warning, and a small Feed button above the quest tracker while the
pet is hungry (`UI/FeedButton.lua`, placed by screen position rather than
anchored to the tracker, so the tracker can still move in combat), a "Pet
care" key binding (`Bindings.xml`, `UI/FeedKey.lua`: a hidden secure button
the key clicks, its macro kept up to date out of combat; since 2026-10-11 it
also calls the pet with none out, revives a dead one, `[@pet,dead]` and
`petDead` when its body is gone, and summons a warlock's last demon, kept per
character in `lastDemon`, never rename it; in combat with the pet alive it
casts Mend Pet, `[@pet,exists,nodead,combat]`; and a second key, "Dismiss pet",
is its own secure button `BlackthornesPetsDismissKey` that only casts Dismiss
Pet, 2026-10-11), and the
taming skills on a beast's tooltip (`Logic/Taming.lua`,
`UI/TamingTooltip.lua`), from `Data/BeastSkills.lua`, which is generated from
the Classic world database's copy of Classic 1.12's CreatureSpellData, never
typed by hand. `Logic/TameRecord.lua` records, account wide, what a beast
teaches on Forever by reading the new pet's bar right after Tame Beast;
The owner's `/bpet tamed` output is how new Forever beasts get into the data.
The **Pet Compendium** (`Logic/Compendium.lua`, `UI/CompendiumWindow.lua`,
`/bpet compendium`, asked 2026-10-07) lists every tameable beast in three
layers, the later winning, since data from the Forever client beats anything
online: Classic (`Data/Compendium.lua`, generated by
`tools/make_compendium.py` from the same Classic world database dump as BeastSkills plus
the spawn database's coordinates), then Forever (`Data/ForeverBeasts.lua`, generated by
`tools/forever_beasts.py`: SEEN from Farmer's `Data/Data_Harvested.lua` by
mob name, TAMED from the owner's Pets save (`tamedBeasts` only), FOUND typed
in the tool, each from a published source, kept in the project's private notes: no data site is named in the repo or the game), then this account's own tames.
Never hand-edit either data file. Tame records now also keep `family`,
`zone`, `x`, `y` and `speed` (added fields; nothing renamed). The Speed
column (a player asked, the owner agreed 2026-10-11) is Classic's
`base_attack_time` in seconds, since a Classic pet keeps the speed of the
beast it was tamed from; `TameRecord:PetSpeed` reads `UnitAttackSpeed("pet")`
out of combat at the tame (and once for an older tame when it is called
out, `NoteSpeed`), and that real speed wins. Sorting by Speed puts the
fastest first across every family (2026-10-11; it used to go family by
family, so turning it round barely moved anything with a box ticked).
Every heading follows the house rule: a click sorts, a second turns it
round, a third goes back to by beast (`CompendiumUI:SortBy`), whatever
is ticked. The list's scroll bar takes the mouse (`CompendiumUI.grip`,
wider than it looks), so holding it drags the list, never the window. The
family picker is a dropdown (`Widgets.CreateDropdown`, Tradeskills'
trimmed to one choice; a player asked, the owner agreed 2026-10-11),
sized to its longest family by `Widgets.DropdownWidth`. Before a release, fold
in the owner's tames and the latest Farmer harvest by rerunning
`forever_beasts.py`. The map pin is Equipment's `Logic/Waypoints.lua`.
Beside it: settings, a minimap
button and a read-only `/bpet probe` for the pet calls. The feature ideas are
in the project's brainstorm, not in the repo.

## How this repo was set up

It copies its sisters on purpose, most closely Equipment (the newest and
smallest), so check them before inventing a convention:

- **Layout** `Core/ Data/ Logic/ UI/ Probe/ tools/ docs/`, one module per
  file through `ns.NewModule`, no Ace3 or LibStub. `Core/Init.lua` is
  Equipment's (itself Farmer's), renamed. The global is `_G.BlackthornesPets`,
  the commands `/bpet` and `/pets`, the saved data `BlackthornesPetsDB`
  (account: window positions, minimap, debug) and `BlackthornesPetsCharDB`
  (per character, because pets belong to one character).
- **Palette** is the house one (`ns.COLORS`), with `good` and `bad` in
  Tradeskills' profit green and loss red. `UI/Theme.lua`, `UI/Widgets.lua`,
  `UI/Minimap.lua` and `UI/Settings.lua` are Equipment's with the gear parts
  taken out. The minimap button starts at 260 degrees, clear of Tradeskills'
  at 170, Farmer's at 200 and Equipment's at 230.
- **Tools** (`syntaxcheck`, `lintcalls`, `runtests`, `check_release`,
  `check_package` and their tests, `link.ps1`) are Equipment's with the names
  changed. If one of them gets a fix in a sister repo, bring it here too.
- **Tests** are `tools/test_*.lua`, found by name. `tools/testenv.lua` loads
  the files the TOC lists, so there is no second list to keep.
- **PRs** follow the sisters' habit: a "Before:" and an "After:" paragraph
  in plain words, then a short "How" naming the functions and tests touched,
  that the checks pass, and whether `/reload` is enough. Release PRs are
  `release/X.Y.Z` branches titled "Changelog for X.Y.Z".
- **API findings** go in `docs/FOREVER_API_FINDINGS.md`. Tradeskills' and
  Equipment's files of the same name record what the Forever client does for
  their areas; read them before relying on an API.

Nothing here calls the other addons, and nothing calls this one, apart
from the shared arrow table below and Blackthornes Butler's one read-only
call (see "What Butler calls here"). If that changes, write down the global and the calls
in both repos' `CLAUDE.md`, the way Farmer and Tradeskills do for prices
and goals.

## What Butler calls here

**Blackthornes_Butler** (`Blackthornes/Blackthornes_Butler`) tells the
player what to do with each bag item, and asks here whether the pet wants
it. It calls, inside a pcall and only when this addon is loaded:

```lua
_G.BlackthornesPets.Butler:Advise(itemID)  -- a table, or nil; never raises; reads only
```

`Logic/Butler.lua` answers for the character playing and the pet it has
out, nil when there is no hunter pet that eats (no pet, a warlock, a client
that names no diet), when the item is not in `Data/PetFood.lua`, or on any
error. Otherwise:

- `eats`: true when the pet eats the item (its diet, and not 30 or more
  levels below the pet); false for pet food of another diet or too low.
- `buff`: true for buff food (`Food:IsBuffFood`), which is fed last.
- `hours`: about how long all the food the pet is fed from the bags lasts,
  to a tenth of an hour, by the classic rule (35,000, 17,000 or 8,000
  happiness a piece by `Food:Effect`, 670 lost every 7.5 seconds); 0 with
  none, nil while the bags are not all read. The same for every item.
- `count`: how many of the item are carried among the food the pet is fed;
  0 for food it eats that is not carried; nil when not known (food it does
  not eat, buff food with "Never feed buff food" ticked, or bags not all
  read).

- `keepAll`, `keep`, `extra` (Food to Keep, the owner said build it from
  a mockup, 2026-11-20): only while "Food to Keep:" (Settings, Pet page,
  FEEDING; `keepFood`, off unless ticked, and `keepFoodCount`, 40, 5 to
  200; never rename either) is ticked and the bags are all read, and only
  for carried food the pet is fed. `keepAll` is the number kept; it is
  shared out best first (`Food.KeepPlan`, the food fed first is kept), so
  `keep` is how many of this item stay and `extra` how many Butler may
  mail to its bank alt. Buff food left out by Never Feed Buff Food has
  neither. Butler never sells or deletes food for it.

Butler asks once per bag item, a hundred in one frame, so the pet and the
food (`Food:Latest`, itself kept between bag events) are read once and kept
until `Food:BagsChanged` or the clock moves on (`Butler:Reading`); no timer.
Keep the global, `Butler` and `Advise(itemID)` with these fields stable; if
one has to change, change Butler's `Logic/Sisters.lua` too. Tested in
`tools/test_butler.lua`.

## German translation

The owner said yes (2026-10-11) to a German translation, piloted here
before the other four. Players are told the language as "Deutsch", or
"Deutsch (German)" where English readers need it; the code names stay
`deDE` and `Locale/deDE.lua`.

- **English is the key and the fallback.** `Locale/Locale.lua` (first in
  the TOC) makes `ns.L`, whose missing keys answer the key itself, so
  `L["Feed"]` is "Feed" until a translation fills it in. `L.Format(key,
  ...)` is `string.format` on the translation, and puts values named by
  place (`%2$s ... %1$d`) in order where German word order needs them,
  since the tests' Lua 5.1 cannot.
- **Adding a string:** write it as `L["English text"]` or
  `L.Format("English %s", value)`, a literal where it is written (a key
  built at run time cannot be checked), add its line to `Locale/deDE.lua`
  (informal "du" and the game's own German words: Begleiter, Wildtier,
  Zähmen, Tierausbildung, Futter, Stufe, Meter), and run
  `python tools/check_locale.py`, which lists keys with no German line and
  German lines no longer used. It only warns (the tests workflow runs it
  as a warning); keep it at 0 missing. `tools/test_locale.lua` loads the
  addon as a German client.
- **Left in English on purpose:** slash command words, saved and internal
  keys, anything compared against data, data names (beasts, families,
  zones; skill and item names come from the client), `Probe/` output, the
  arrow check and debug lines (they are for us), `/bpet tamed`'s paste
  lines, and spell names a macro casts.
- German runs about 30% longer: buttons grow to fit, settings rows wrap,
  and a new fixed width must wrap or grow, never end in "...".
- `Locale/Locale.lua` and `tools/check_locale.py` are meant to be the same
  in all five addons; once the others have them, a fix to either belongs
  in all five. `Core/SisterNote.lua`, `UI/SettingsPages.lua` and
  `UI/Titanforged.lua` read `ns.L` with an English stand-in, so they still
  work unchanged in an addon without `Locale/`.

### One key per character

The owner asked (2026-10-11) that a character can never be mistaken for
another again. Old records had sent errands to the character playing:
Butler filled a mail to itself and told a player to mail Medium Leather to,
and log out for, the character they were on (an old "Name-Realm" record of
Tradeskills' beside the GUID one), and a reload wiped alts' saved gear in
Equipment. The rule, in every addon:

- **A character is its GUID** (`UnitGUID("player")`) in saved data and in
  every call between the addons. Never a first name, "Name-Realm" or a
  short name: Forever lets characters share a first name. Names are for
  showing and for a mail's To line only, always first and last.
- **A GUID the client won't read (a dungeon) means "not sure who's
  playing":** write nothing under another key, and offer nothing for an
  alt. Tradeskills remembers each character's GUID in its own file
  (`BlackthornesTSCharDB.guid`) for that case.
- **Old records stay readable and count as the same character; nothing is
  deleted.** Tradeskills folds an old "Name-Realm" record into the GUID one
  at login, once (`Config:AdoptLegacyCharacter`): it is kept whole in
  `formerCharacters[old key]` with `retiredInto` (never rename either), what
  the GUID record lacks is filled from it when it carries that GUID, and
  the queue's references to the old key follow. Farmer reads a goal tagged
  "Name-Realm" as the character's and tags it with the GUID once the
  character gathers toward it or changes it.
- **One test per addon answers "the same character?" and "the one
  playing?"; never compare keys or names by hand.** Tradeskills:
  `Characters:Same`, `:IsPlaying` and `:Canonical` (`Core/Characters.lua`),
  and `playing` on each `Butler:Holdings()` entry. Butler:
  `Errands:IsMe(name)` (full name, first name alone, any old record's name,
  any case, with or without a realm). Farmer: `Goals:IsOwner`. Equipment:
  `Alts.PlayerGUID()`.
- **Every errand that targets a character asks that test right before it
  acts and refuses the character playing:** a mail, a gold top-up, a Log
  out, an alt's upgrade, a learned habit, the disenchanter.
- Tested in Tradeskills' `tools/test_onecharacter.lua`, Butler's
  `tools/test_notme.lua`, Farmer's `tools/test_goals.lua` and Equipment's
  `tools/test_alts.lua`. This rule is in every addon's notes; keep them the
  same.

## Checking a change

The owner said yes (2026-11-16) to five ideas from the Claude Code team's
writeup on verification, in all five addons, after fixes kept passing the
tests and then needing a fix in game (the one window snapping back mid-drag,
TSM Sold a Day). The same in every addon; keep them the same.

- **The verify recipe** (`.claude/skills/verify/SKILL.md`), followed before
  every PR. A bug fix starts with a test that fails the way the game failed,
  then passes with the fix. The steps are acted out in the fake game
  (`tools/testenv.lua`, or Tradeskills' module stubs), and when the fake game
  allowed something Forever does not, it is fixed in the same PR.
- **The change checklist** (`Docs/change-checklist.md`,
  `tools/checklist_for_change.py`). Past misses, each with a trigger read
  from the diff (`Files:` a path pattern, `Lines:` a pattern on changed
  lines), a `Check:` and a `Why:`. The tool prints only the items a change
  touches. A miss a diff could have shown gets an item in its fix's PR; an
  item goes when the code it guards does. `tools/test_checklist_for_change.py`
  checks every item is whole.
- **How it was checked.** Every PR body ends with `Checked: tests | fake
  game | in game | none yet` (each that is true) and `Not checked:` (what
  only the real game shows). "in game" only after the owner saw it.
- **House rules** (`tools/check_house_rules.py`, tested by
  `tools/test_check_house_rules.py`). Looks at lines a change adds, against
  origin/main: em-dashes, hype words and questions in `L["..."]` and
  `L.Format("...")`, and the old `row`/`rowAlt` list bands. A line kept on
  purpose ends with `-- house-ok`. `--all` reports the whole addon (older
  lines still use the old bands in a few places). CI runs it on each change
  as warn only.
- **Always-true tests** (property tests): `tools/test_properties_window.lua`
  (the same in all five: a window's spot comes back at any UI scale, the
  size setting stays in range), `tools/test_properties_serialize.lua`
  (Farmer and Tradeskills: shared data comes back the same, broken text
  never raises), and `tools/test_properties.lua` (Tradeskills: Characters:Same;
  Butler: Errands:IsMe). Fixed seeds, so a failure repeats. The window test
  found that `SharedWindow.Clamp` let not-a-number through (2026-11-17); the
  owner said fix it, and a bad size in a save now reads as 100
  (`UI/SharedWindow.lua` FILE_VERSION 12, in all five).
- **Three tries, then ask.** A check still failing after three rounds stops
  the work. Never skip, loosen or rerun a test to get green.
